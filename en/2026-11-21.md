Day 29 of fermentation. inajob's mdesk is a project, going since September, to build a desktop environment on an ESP32-S3. Today, Japanese input worked on its real hardware. Watching Japanese being typed on that small screen reminded me of the examples that had been catching my eye over the past few weeks: attempts to build desktop-like things with screens on ESP32, RP2350 and RP2040, appearing one after another. Today I made a feature of lining them up. The axes are three: how apps are run, the shape of the screen, and whether Japanese input exists.

## How apps are run

On the axis of how apps are run, they divide like this.

- Native (ELF): [BMDS](https://github.com/jthwho/bmds), [bevel-os](https://github.com/andrisgauracs/bevel-os)
- Native (Zig): [PowerOS](https://github.com/cycl0ne/poweros_esp32)
- Native (built-in programs): [Sylphide OS](https://projects.freehackers.org/sylphide-os/), [esp32_cyd_pda](https://github.com/sau412/esp32_cyd_pda)
- Scripts (Lua): mdesk, [S3_OS](https://github.com/circularchickenthatcodes/S3_OS_for_CYD)
- Scripts (JavaScript): [KryonOS](https://github.com/Haris16-code/KryonOS)
- Scripts (MicroPython / Python): [TinyDesk](https://github.com/tinydesk-project/tinydesk), [mote.](https://mote.kellishaver.com/), [Tulip](https://github.com/shorepine/tulipcc), [Picoware](https://github.com/jblanked/Picoware), [MicroHydra](https://github.com/echo-lalia/MicroHydra)
- Wasm: [KoaOS](https://github.com/Koakno/KoaOS-for-the-Heltec-V4)
- Bytecode: [KotoOS](https://github.com/siska-tech/KotoOS)
- Served to a browser: [NucleoOs](https://github.com/indecenti/NucleoOs) (the desktop screen is served as a web page)
- Remote display: an [X11 server](https://github.com/serg5z/woodland-x11) on ESP32-S3

## The shape of the screen

The shape of the screen divided into three: windowed desktops, launchers, and dedicated devices. For the ones with screens, the explanation comes after the quote.

![bevel-os desktop](https://raw.githubusercontent.com/andrisgauracs/bevel-os/main/docs/img/cover.png)

[**bevel-os**](https://github.com/andrisgauracs/bevel-os) (ESP32-S3). A Windows 95-style windowed desktop. It boots in 0.7 seconds, Doom runs at 32fps, and the OS itself was reportedly written by Claude Fable 5.2. From the README of [andrisgauracs/bevel-os](https://github.com/andrisgauracs/bevel-os).

![BMDS desktop](https://media.githubusercontent.com/media/jthwho/bmds/main/docs/images/desktop.png)

[**BMDS**](https://github.com/jthwho/bmds) (ESP32-P4). A windowed desktop where a terminal, a file manager and a system monitor sit side by side. It runs ELF binaries as they are. From the README of [jthwho/bmds](https://github.com/jthwho/bmds).

![PowerOS desktop](https://raw.githubusercontent.com/cycl0ne/poweros_esp32/main/docs/screenshots/desktop-work.png)

[**PowerOS**](https://github.com/cycl0ne/poweros_esp32) (ESP32-S3 and ESP32-P4). A windowed desktop written in Zig. From [cycl0ne/poweros_esp32](https://github.com/cycl0ne/poweros_esp32).

![Sylphide OS on real hardware](https://projects.freehackers.org/sylphide-os/images/overview.avif)

**[Sylphide OS](https://projects.freehackers.org/sylphide-os/)** (ESP32-P4 and RP2350). A general-purpose OS for computers made from microcontrollers, built on FreeRTOS with its own drivers and a windowed GUI on top. Its targets are Olimex's ESP32-P4-PC, a home-made RP2350 board, and FabGL; the photo shows the RP2350 side driving a VGA monitor. Its programs are built in for now; loading executables from an SD card is planned for later. It is Thomas Capricelli's project, and the source lives in a Mercurial repository. From the [Sylphide OS](https://projects.freehackers.org/sylphide-os/) project page.

![KryonOS home screen](https://raw.githubusercontent.com/Haris16-code/KryonOS/main/Documentation/assets/imgs/kryonos-home.jpg)

[**KryonOS**](https://github.com/Haris16-code/KryonOS) (ESP32 and ESP32-S3). Apps are written in JavaScript, with a launcher, a file manager and an App Store on top of the Duktape runtime. It was featured on Hackster this week. The home screen is close to the desktop type. From [Haris16-code/KryonOS](https://github.com/Haris16-code/KryonOS).

![TinyDesk desktop](https://raw.githubusercontent.com/tinydesk-project/tinydesk/main/docs/media/desktop-demo-esp32.gif)

[**TinyDesk**](https://github.com/tinydesk-project/tinydesk) (ESP32). A desktop whose windows you move with a mouse. Apps are written in MicroPython. Version 0.3.0 came out this month, and it now runs on the CrowPanel 7.0's 800×480 touch screen too. From [tinydesk-project/tinydesk](https://github.com/tinydesk-project/tinydesk).

![NucleoOs screen](https://raw.githubusercontent.com/indecenti/NucleoOs/main/docs/screenshots/webos.gif)

[**NucleoOs**](https://github.com/indecenti/NucleoOs) (M5Stack Cardputer, whose core is an ESP32-S3). The body is firmware written with ESP-IDF, and there is a display on the device's own small screen. But the real desktop is a web page the device serves from its SD card, which you open in a browser on a PC or phone on the same network. The quoted GIF shows that served side. Because the heavy rendering is pushed to the browser, a windowed desktop works even on an ESP32-S3 with no PSRAM. From [indecenti/NucleoOs](https://github.com/indecenti/NucleoOs).

![MicroHydra screen](https://github.com/echo-lalia/Cardputer-MicroHydra/assets/108598670/15b78e4b-64fc-433a-86d3-979362abd9ab)

[**MicroHydra**](https://github.com/echo-lalia/MicroHydra) (M5Stack Cardputer, whose core is an ESP32-S3). An app switcher made in MicroPython, a launcher type with the face of an OS. From [echo-lalia/MicroHydra](https://github.com/echo-lalia/MicroHydra).

![mote. launcher](https://mote.kellishaver.com/img/02_launcher.png)

[**mote.**](https://mote.kellishaver.com/) (Waveshare's ESP32-S3 AMOLED board). A small OS in MicroPython, with a launcher you pick from by touch. From [mote.](https://mote.kellishaver.com/).

![Tulip editor](https://raw.githubusercontent.com/shorepine/tulipcc/main/docs/pics/editor.png)

[**Tulip**](https://github.com/shorepine/tulipcc) (ESP32-S3). Not the windowed type: when it boots, a Python prompt and an editor come up — the dedicated-device type. It is for music, graphics and writing, made with MicroPython and LVGL, and you can buy it from Makerfabs for 59 dollars. From [shorepine/tulipcc](https://github.com/shorepine/tulipcc).

![Picoware desktop](https://raw.githubusercontent.com/jblanked/Picoware/main/images/desktop-animation.gif)

[**Picoware**](https://github.com/jblanked/Picoware) (RP2040 and RP2350, ClockworkPi PicoCalc). Firmware with a desktop screen, of the launcher type. From [jblanked/Picoware](https://github.com/jblanked/Picoware).

![KotoOS memo app](https://raw.githubusercontent.com/siska-tech/KotoOS/main/docs/images/memo.png)

**[KotoOS](https://github.com/siska-tech/KotoOS)** (RP2040 and RP2350, ClockworkPi PicoCalc). A Japanese PDA environment written in Rust, targeting the same PicoCalc as Picoware. Apps run as its own bytecode, and the home screen is a launcher. It has an SKK Japanese input method; the quote shows the memo app mid-conversion, from the simulator that renders the same screen as the device. From [siska-tech/KotoOS](https://github.com/siska-tech/KotoOS).

![DECK//OS home screen](https://raw.githubusercontent.com/hey-its-brian/tab5-cyberdeck/main/docs/screenshots/home.png)

[**DECK//OS**](https://github.com/hey-its-brian/tab5-cyberdeck) (ESP32-P4, M5Stack Tab5). Firmware for a cyberdeck with a keyboard, of the dedicated-device type. From [hey-its-brian/tab5-cyberdeck](https://github.com/hey-its-brian/tab5-cyberdeck).

![Kode Dot hardware](https://raw.githubusercontent.com/kodediy/KodeOS/main/.github/img/kode-dot-front.png)

[**KodeOS**](https://github.com/kodediy/KodeOS) (ESP32-P4, Kode Dot). An OS for a small device, of the dedicated-device type. From [kodediy/KodeOS](https://github.com/kodediy/KodeOS).

![X11 running on a CrowPanel](https://raw.githubusercontent.com/serg5z/woodland-x11/main/site/img/crowpanel-x11-1280.jpg)

[**X11 server**](https://github.com/serg5z/woodland-x11) (ESP32-S3, Elecrow CrowPanel Advance 4.3-inch). The remote-display form: apps run on another machine and only the screen is shown here. IKeJI posted it on Discord on November 14. From [serg5z/woodland-x11](https://github.com/serg5z/woodland-x11).

![esp32_cyd_pda screens](https://raw.githubusercontent.com/sau412/esp32_cyd_pda/main/Collage.png)

**[esp32_cyd_pda](https://github.com/sau412/esp32_cyd_pda)** (ESP32, CYD). PDA firmware inspired by Palm OS, with PIM apps built in — notes, contacts, a schedule, expenses. You add apps by modifying the Arduino code, and the screen is a touch launcher. It targets the same CYD as S3_OS, but its shape is a personal organizer, not a desktop. From [sau412/esp32_cyd_pda](https://github.com/sau412/esp32_cyd_pda).

![ESP-Osito file manager](https://raw.githubusercontent.com/ralsina/esposito/main/apps/file_manager/file_manager.png)

**[ESP-Osito](https://github.com/ralsina/esposito)** (ESP32, CYD). An OS that treats the 10-dollar CYD as a real computer, by Roberto Alsina. Apps are written in C or C++, and when one loads it completely replaces the previous one. There is no multitasking. It boots in under a second, and even if you cut the power, the same app comes back in the same state. It has an ebook reader, a file manager, a terminal and more, and the screen opens full-screen apps from a launcher. From [esposito.ralsina.me](https://esposito.ralsina.me/).

![CL-32 hardware](https://cdn.hackaday.io/images/1982531787870650023.jpg)

**[CL-32](https://hackaday.io/project/197467-cl-32)** (ESP32-S3). This one is not an OS but dedicated hardware to receive one. A pocket terminal with an e-paper screen and a physical keyboard, and one of the machines SolarOS targets. The photo sets it beside a vintage pocket computer, the CASIO PB-100, the two screens trading a parent-and-child exchange. From [Hackaday.io](https://hackaday.io/project/197467-cl-32).

Let me also write down the group with no screen to quote.

- [KoaOS](https://github.com/Koakno/KoaOS-for-the-Heltec-V4) (ESP32-S3): Wasm apps can be added dynamically. The base is FreeRTOS, with a UNIX-like shell and capability-based permissions. inajob himself wrote a review of it on November 17. There are no images in the repository
- [S3_OS](https://github.com/circularchickenthatcodes/S3_OS_for_CYD) (CYD): it has a file explorer and a Lua interpreter built in, on the same Lua side as mdesk. There are no screen photos, only app icons
- [PyDOS](https://github.com/RetiredWizard/PyDOS): on top of MicroPython, it puts up a DOS-like text screen
- [SolarOS](https://github.com/nilseuropa/solar_os) (ESP32): an OS for pocket terminals with screens, targeting 28 models with e-paper or LCD. The display is text-first, and it boots into a shell. It has foreground apps and background jobs, and its scripts are Lua and Python. There is no published image of it running. Among its hosts is the dedicated hardware [CL-32](https://hackaday.io/project/197467-cl-32)
- [thistle-os](https://github.com/wan0net/thistle-os) (LilyGO T-Deck Pro): still at the stage of screen design concepts

![thistle-os screen design](https://raw.githubusercontent.com/wan0net/thistle-os/main/docs/design/visual-language/phone-home-landscape-concept.png)

thistle-os's screen design (a concept drawing). From [wan0net/thistle-os](https://github.com/wan0net/thistle-os).

## Whether Japanese input exists

What the overseas examples have in common is that they have no Japanese input. When ikeji wrote of BMDS in a review roundup on November 19, "if only it could read and write Japanese," that was about this axis. In a minimal design like [Sylphide OS](https://projects.freehackers.org/sylphide-os/), an IME is the first requirement to fall. That mdesk kept SKK even while cutting everything down to the practical line is the reverse of that. To write in Japanese, without an input mechanism, typing itself cannot begin.

There were examples that did include Japanese input.

![Clientre5 hardware](https://raw.githubusercontent.com/Mozgi512/Clientre5/main/docs/photos/tab5-jis-keyboard.jpg)

[**Clientre5**](https://github.com/Mozgi512/Clientre5) (ESP32-P4, M5Stack Tab5). An SSH terminal OS that supports Japanese input. There is a photo of the real device with a keyboard customized to a JIS layout. As a terminal that fits in a pocket, it is built on the idea that you need to type, not just read. From [Mozgi512/Clientre5](https://github.com/Mozgi512/Clientre5).

On the side with Japanese input, there was also a Japanese example, [KotoOS](https://github.com/siska-tech/KotoOS). The same SKK as mdesk, and the same Rust.

Right after it worked, inajob wrote on Discord that, with the speed problem, he might drop the Lua layer.

> <!-- speaker: inajob -->
> There's an issue with speed, so maybe I'll stop putting the Lua layer in...

mdesk was originally something inajob made himself in C/C++ and Lua, and had OpenCode rewrite from zero in Rust+Lua. Its apps run as Lua scripts. Whether to remove that layer is not decided yet. It was the next question, on the very day Japanese input worked.

The screens I quoted are not all windowed desktops. There are launchers, an editor, and an e-paper terminal too. Among them, the ones that go as far as Japanese input were only three: mdesk, Clientre5 and KotoOS. mdesk's photo from today is the plainest of them. And still, the input that worked today worked on the plainest desktop.
